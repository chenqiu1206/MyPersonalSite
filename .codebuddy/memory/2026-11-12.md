## 切换控件最终形态：层叠卡片抽换（Card Stack + Z-order Swap）

用户反馈错落方案「效果不好」，并描述为「两张扑克牌，切换就是把后面那张放到前面」。

**术语**：业界没有唯一标准名，最贴近的组合是 **Card Stack + Z-order Swap**（层叠卡片抽换），属于 Spatial Transition（空间转场）。易混项：Cover Flow（横向层叠滚动）、3D Flip Card（翻面）。

**实现**（`Experience.vue`）：

- 容器 `relative mr-2 h-9 w-28`，两个按钮 `absolute inset-0` 完全重叠
- 当前项：`z-20 scale-100 rotate-0` + `bg-white` + `border-line` + 极淡投影 → 上层
- 另一项：`z-10 scale-95 translate-x-2 translate-y-1 -rotate-2` + 更淡的边框与文字 → 下层露出右下角
- 切换时两者互换：上层缩小/下沉/右移/逆时针 2°/变淡，下层放大/回正/上浮/变深
- `transition-[transform,color,background-color,border-color,box-shadow] 460ms` + 与折叠相同的缓动曲线
- `mr-2` 预留右移空间，避免下沉那张溢出内容右边界
- 构建通过（CSS 33.55KB / gzip 6.60KB），lint 0

**教训**：纯文字做「前后」必须真的重叠，只错位读不出层级；一旦要牌感就绕不开卡片容器（bg + border + 投影），与「去块状」有冲突，这是用户主动选择的结果。

## 最终改为 3D 翻转对调（Card Flip / Rotate Swap）

用户澄清：「社会实践相当于工作履历的阴影一样在其后方，切换时两者绕空间旋转位置对调」。

**术语**：**Card Flip / Rotate Swap**（翻转对调），属于 3D spatial transition。与之前的 Z-order Swap（平面层级交换）不同——这次是真的绕 Y 轴在 3D 空间里转。

**实现**（`Experience.vue`）：

- 外层 `[perspective:900px]` 提供透视深度
- 内层 `[transform-style:preserve-3d]`，切换时 `transform: rotateY(180deg)`，**720ms** + 与折叠相同的缓动
- 两个按钮 `absolute left-0 top-0 h-9 w-full`，`[backface-visibility:hidden]` 保证只显示朝向观众的那一面
- 正面（工作履历）：`translateY(0)`
- 背面（社会实践）：预置 `rotateY(180deg)`，未被选中时再 `translateY(3px)`，在后方露出 3px 底边，形成「影子/第二张牌」的存在感
- 切换时两者同时互换 `translateY`：露出边的那张归位、另一张下沉，配合容器翻转，"后面的牌转到前面"
- 容器 `h-10` 比牌 `h-9` 高 4px，容纳下沉部分
- 产物确认 `perspective:900px` / `transform-style:preserve-3d` / `backface-visibility:hidden`，构建通过（CSS 32.57KB）

**注意**：旋转到 90° 时两面都不可见（牌变成一条线），这是 3D 翻转的固有特性，不是 bug。

## 修复切换控件点击失效（同日追加）

用户反馈：「两个叠加在一起了你让我怎么切换」。

**根因**：两个 `<button>` 都是 `absolute left-0 top-0 h-9 w-full` 完全重叠，同 z-index 时 DOM 靠后的「社会实践」压在最上层。当 `view === 'social'` 时，点击命中的仍是它自己，视图不变，**无法切回**。

**改法**：

- 两个文字降级为 `<span>` + `pointer-events-none`，纯展示、不参与命中测试
- 切换交给外层容器：`role="button"` + `tabindex="0"` + `@click.stop` + `@keydown.enter` + `@keydown.space`，整块都是热区
- `aria-label` 动态播报「当前是 X，点击切换到 Y」
- 顺带修可读性：退后的那张加 `translate(6px,4px)`，不再与前字完全重叠，避免糊成重影
- 容器改为 `mr-2 h-10`，为下沉偏移留空间
- 构建通过（CSS 32.63KB / gzip 6.58KB），lint 0

**教训**：绝对定位叠放的可交互元素必须只有一个「命中层」。多个按钮重叠 = 只有一个能点，这是结构性问题，不是样式问题。

## 修复「切换位置没有平移动画」（同日追加）

用户反馈：「两者位置切换也要有平移动画」——实际上位置此前一直是瞬移的。

**根因（Tailwind v4 关键差异）**：v4 的位移 / 缩放 / 旋转工具类改用**独立 CSS 属性**，不再是 `transform`：

```css
.translate-x-10 {
  --tw-translate-x: calc(var(--spacing) * 10);
  translate: var(--tw-translate-x) var(--tw-translate-y);
}
```

同理 `scale-*` → `scale` 属性、`rotate-*` → `rotate` 属性。

而过渡写的是 `transition-[transform,color,opacity]`，这两个元素上 `transform` 属性根本没变化 → 永远不会有平移过渡。

**修复**：`transition-[transform,color,opacity]` → **`transition-[translate,color,opacity]`**
**验证**：产物生成 `transition-property:translate,color,opacity` ✓

**顺带排查的其他位移动画，均无此问题**：

- 侧栏滑动高亮块：内联 `style="transform: translateY(...)"` + `transition-[transform,...]` ✓ 匹配
- 抽屉：scoped CSS 里 `transform: translateX(-100%)` + `transition: transform` ✓
- 板块折叠：`grid-template-rows` ✓ 不涉及
- 汉堡按钮：`transition-all` ✓ 覆盖全部属性
