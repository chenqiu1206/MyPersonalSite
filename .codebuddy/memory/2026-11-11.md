## 关键实现决策

- **横向分栏条件**：`(min-width: 900px) and (min-aspect-ratio: 1/1)`，同时用 `matchMedia` 驱动 JS 渲染判断，避免 CSS/JS 双份条件不同步。窄屏时不渲染 `<aside>`，主内容自然占满宽度。
- **滚动高亮**：不用 IntersectionObserver，改为「视口 30% 单条判定线 + 取最后一个越过判定线的板块」，边界只切换一次，不抖。
- **程序化滚动锁**：导航点击后 `lockTo(id)` 锁定高亮；滚动停止 120ms 后解锁重算，另设 900ms 兜底，防止平滑滚动途中高亮逐个掠过。
- **折叠动画**：`grid-template-rows: 0fr ↔ 1fr` + 内层 `overflow-hidden`，无需测量高度，不跳变；收起时加 `inert` 防止焦点进入。
- **导航二次点击语义**：目标非当前板块 → 滚动定位；已是当前板块 → toggle 展开（需求写「展开」，实现为可收起的 toggle）。

## 恢复动画 + 导航高亮改为滑动块（同日追加）

用户反馈「没有动画效果」，选择方案 A + D。

### A. 修复 prefers-reduced-motion 误伤

`style.css` 原规则用 `!important` 把所有 `transition-duration` 压到 0.01ms。系统开启「减少动态效果」时（Windows 关闭「显示动画」/ macOS 开启「减弱动态效果」），整站过渡全部消失。

改为只禁用关键帧动画：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

同时移除 `transition-duration` 与 `scroll-behavior: auto`（平滑滚动已由 `useNavigation.js` 里的 `prefersReducedMotion()` 单独判断）。

### D. 导航高亮滑动块

- `ul` 内只保留**一个** absolute 高亮块（渐变底 + 2px 竖条），替代每个导航项各自的渐变层
- 位置由 `updateIndicator()` 计算：`button.offsetTop` / `button.offsetHeight`（button 是 recent 定位祖先为 `ul.relative` 的元素，li 不定位）
- `transition-[transform,height,opacity] duration-300 ease-soft`
- `animated` 标志：首帧定位后 400ms 才开启过渡，防止高亮块从左上角滑入
- 监听 `activeId`、`sections.length`、`window.resize`、`ResizeObserver(ul)`
- 导航项移除自身渐变层与竖条，保留文字颜色过渡；button 加 `relative z-10` 压在滑块之上
- 间距由 `space-y-1.5` 改为每个 `li` 的 `pb-1.5`（`space-y` 的 margin 会干扰绝对定位块）
- 产物确认 `transition-property:transform,height,opacity`

### 折叠动画增强
